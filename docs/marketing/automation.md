# 認知施策の自動運用

開始日: 2026-10-24

## 目的と現在の状態

PC版ChromeでFANZAを視聴する人へ、時刻付きメモ・頭出し・ABリピートの使い方を届ける。初期運用は日本語を中心にする。

このチャットに、毎週月曜・木曜の午前9時（日本時間）の定期実行を登録済み。原稿作成と運用状況の確認を進める。Xの投稿先はユーザー指定の [@awawawawawadama](https://x.com/awawawawawadama)。投稿用API接続は未接続で、記事の公開先と計測接続も未設定。外部への投稿や公開の成功を示す記録はまだない。

その後のユーザー指定により、追加費用0円を優先する。公式X APIはユーザーが利用中との申告があるが、この作業環境での接続確認は未実施で、投稿作成APIは従量課金のため呼び出さない。定期実行では原稿作成まで行い、無料の手動投稿を前提とする。既存の定期実行登録は本番の自動配信基盤とは区別し、本書の更新によるスケジュール変更・公開開始は行っていない。

認知からインストールまでの全体戦略案は [認知獲得・インストール促進戦略](acquisition-strategy.md) に記録する。追加費用0円を維持するため現行のZIP配布を続け、X投稿APIは使わない。専用アカウントや週3回程度の投稿、Chrome Web Store限定公開は案であり、現在の投稿先・週2件の原稿上限・配布方式を変更するものではない。

正本は本書と `queue.json`。Xは原稿作成までを自動化し、投稿APIは呼び出さない。ユーザーが無料の手動投稿を行ったことを確認できる根拠がある場合のみ公開済みと記録する。追加費用の発生する手段は選ばない。

## 1回の実行内容

1. `AGENTS.md`、`docs/requirements_definition.md`、配布中の拡張・LPの実態を照合する。対応範囲や価格、導入方法が変わったときは原稿にも反映する。
2. `queue.json` と過去の実行記録を読む。未配信のX原稿が2件ある場合は、新しい原稿を積み増さず、既存原稿の根拠・リンク・接続状況を確認する。
3. 異なる困りごとを解決するX原稿を最大1件用意する。月曜は、未公開の記事下書きがなければ、具体的な操作手順を含む記事を最大1本用意する。導入・時刻付きメモ・ABリピート・バックアップを順番に扱う。
4. 原稿ごとに裏付けとなる仕様やファイルを記録する。「公式」「完全オフライン」「完全匿名」「全プレーヤー対応」「自動更新」など、実態と異なる表現を使わない。
5. X原稿を最大1件作る。API投稿・API予約は行わず、公開は無料の手動投稿とする。X原稿は週2件、記事原稿は週1本を上限とする。追加の言語展開や件数増加は、実績をもとに提案する。
6. ユーザーの手動投稿を示す公開URLが確認できた場合のみ `published` と記録する。原稿を作っただけでは予約・公開済みにしない。
7. 月曜は接続済みのSearch Console、LP計測、SNS計測を確認する。取得できない指標は「未接続」または「未取得」と記録し、推定値を実測扱いしない。
8. 実行日ごとの記録を `runs/` に保存する。新しい成果、公開・予約の完了、失敗、ユーザーが対応する必要がある変更のみ通知する。同じ未接続状態を繰り返し通知しない。

## 投稿内容と接続

- Xの投稿先はユーザーから2026-10-24に指定された `https://x.com/awawawawawadama`。アカウント指定をAPI接続の確認とは扱わず、接続時には対象アカウントが一致することを照合する。記事公開先は未指定。初期原稿では、非公式の個人開発ツールであることとPC版Chrome向けであることを説明する。
- Xへの公開操作は行わず、ユーザーの無料手動投稿を前提にする。投稿APIとブラウザー画面のスクリプト操作による自動投稿は行わない。自動返信・DM・いいね・フォロー・不特定コミュニティへの書き込みも今回の運用対象に含まれない。
- 画像を添付する場合は、利用権限のある操作画面やダミーデータを使い、実際の利用者のメモや履歴を素材にしない。
- 本文の言い換えだけで同じ宣伝を繰り返さず、操作方法や解決する問題に違いを持たせる。記事は、実際の機能で回答できる疑問がある場合に作成する。
- X APIは投稿作成に従量料金が発生するため、0円運用中は呼び出さない。ユーザーの手動投稿を前提にし、Metricool等の追加契約も行わない。
- LPのcanonical URLはユーザー指定の Cloudflare Pages `https://scene-memo.pages.dev/`。2026-10-24に本番 `main` へ反映し、LP・ガイド・ZIP・画像・言語ファイルのHTTP 200、英語表示、ガイド画面を確認済み。中国語・韓国語の実ブラウザー表示とSEO効果は未確認。

## 計測と改善

検索表示回数 → 検索クリック・SNSリンククリック → LP訪問 → ZIPクリック → 導入完了の申告、の順で状況を確認する。ZIPクリックからインストール数や継続利用者数は算出しない。拡張機能内のコメント本文・動画情報を集客用に取得しない。

投稿リンクは確認済みのLP canonical URLを使う。UTMを集計できる無料手段が確認できた場合のみ `utm_source=x&utm_medium=organic_social&utm_campaign=scene_memo_awareness&utm_content=<原稿ID>` を付ける。集計できない間はUTM別流入を未取得と記録する。

計測は無料のSearch ConsoleとCloudflare Web Analyticsを優先し、新しい契約・登録料・従量課金は発生させない。Cloudflare Web Analyticsの現行仕様はUTMクエリとカスタムイベントに対応しないため、これを有効化してもUTM別流入・ZIPクリックは計測済みにならない。接続状態と未取得指標は[製品事実・計測確認表](product-facts.md)で管理する。

最初の4週間で、最大8件のX投稿と最大4本の記事を扱う。4週間分の実測を確認できる時点で、流入が増えたか、導入で離脱しているか、扱うテーマが重複していないかを評価し、次の頻度を提案する。数字がなければ、データ不足と必要な接続だけを記録する。

上記は既存登録時点の原稿作成上限。要件整理では、初期ガイドはFANZA向け1本、後続の新規ガイド作成または改善は隔週1回を目安とする案を記録している。記事の実際の公開頻度・基盤は未決定であり、既存の原稿作成上限を公開件数の合意とは扱わない。

## 外部の根拠

- [Xの自動化ルール](https://help.x.com/en/rules-and-policies/x-automation): Web画面のスクリプト操作による非APIの自動化、重複投稿、未依頼の自動返信等に関する制限。
- [MetricoolのX連携](https://help.metricool.com/x-twitter-access-in-metricool-2bt66): X連携の契約条件と料金。導入判断時に再確認する。
- [Google検索のスパムポリシー](https://developers.google.com/search/docs/essentials/spam-policies): ユーザーへの価値を追加しない大量の記事生成に関する制限。
- [OpenAIの定期タスク案内](https://developers.openai.com/training/walkthroughs/scheduled-tasks): ローカルファイルを扱う実行では、コンピューターとデスクトップアプリを起動しておく。
