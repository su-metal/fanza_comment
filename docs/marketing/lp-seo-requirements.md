## 3. 初期対応: LP整理とガイド1本（本番反映済み）

LPと日本語FANZAガイドをCloudflare Pages本番へ反映済み。YouTubeガイドはローカル下書きを作成済みで未公開。ガイド本文の4言語展開は後続範囲とする。

### LP-01: 冒頭で用途が分かる説明（実装・本番反映済み）

- キャッチの近くに、何のツールか、何を保存できるか、どの環境で使うかを1〜2文で明示する。
- 実装コピーは「好きな場面の再生位置を、時刻付きメモで保存。」「保存したメモをクリックすると、その場面から再生。」「PC版Chromeで使う拡張機能です。」。ページタイトルにも「FANZA動画の再生位置を保存」を含める。
- 既存のキャッチコピーを維持し、その近くに用途・保存内容・対応環境を配置する。
- 動画ファイルを保存する製品だと誤解されない説明にする。

### LP-02: 説明の重複を整理（実装・本番反映済み）

- 「ブラウザのまま使える」「メモして好きな場面へ戻れる」という説明を整理し、それぞれのセクションの役割を明確にする。
- 機能理解、対応環境、無料枠、導入、保存場所に必要な情報を残す。
- 推奨する流れは、キャッチと機能説明 → 実物の操作例 → 保存・検索・頭出し → 補助機能 → 料金 → 導入 → FAQ → 使い方ガイド紹介 → 最後のダウンロード。
- インタラクティブな説明用デモの後に、実拡張画面を配置する。

### LP-03: 実際の拡張機能の操作を見せる（実装・本番反映済み）

- LP・ガイドに掲載する実拡張のスクリーンショットは、2026-10-25にUI刷新後の日本語画面へローカルで差し替え済み。英語版、ポップアップ、オンボーディング画面も撮影済み。本番LPへの反映は未実施。実操作の短い動画は今後の候補とする。
- 保存、メモをクリックして頭出しする操作が分かる素材を優先する。
- ダミーのメモや利用権限のある素材を使う。実際の利用者のメモ・履歴を素材にしない。
- AI生成の操作サンプルを残す場合は、実際の動画・実際の拡張機能の画面ではないという既存の説明を維持する。
- スクリーンショットにはローカルの模擬YouTubeプレーヤーと説明用サンプルデータを使用し、実際の動画・利用者のメモ・視聴履歴は含めない。LPとガイドは日本語スクリーンショットを掲載し、英語画面は販促用素材として生成する。

### LP-04: ダウンロードと導入への導線（既存実装を維持）

- 冒頭と末尾からZIPの入手・導入方法へ進めること。
- PC版Chrome向け、ZIPの手動導入であることをダウンロード前に把握できること。
- 解凍、`chrome://extensions`、デベロッパーモード、`manifest.json` のあるフォルダを読み込む流れを維持する。
- 更新・アンインストール前のJSONバックアップ、手動更新の説明を維持する。
- ダウンロード回数やボタンのクリック数を、インストール完了数として表示しない。

### GUIDE-01: LP内のガイド紹介（実装・本番反映済み）

- 長い記事本文のLP内埋め込みや外部ブログのiframe読み込みは行わず、独立URLへ案内する。
- リンク先は同じサイト内の独立URLとし、通常のリンクで到達できるようにする。

## 4. SEO・AIOの要件案

### SEARCH-01: キーワードと検索意図

- LPと初期ガイドの主軸候補は「FANZA 動画 再生位置 保存」。補助表現は「好きな場面」「時刻付きメモ」「動画内ブックマーク」「PCブラウザ」。
- タイトル、見出し、説明文、操作説明、FAQに、各箇所の目的に合う自然な文章として使う。出現回数や密度を目標にしない。
- 「FANZA ブックマーク」だけでは作品のお気に入りと混ざり、「保存」だけでは動画ダウンロードと混ざるため、保存対象を具体化する。
- 「FANZA ABリピート ブラウザ」は機能説明・FAQで扱う。現時点では需要の直接の裏付けが弱いため、最優先の単独記事としない。
- 調査結果は定性的な投稿・レビューの観察。月間検索数、競合難易度、現在のPCブラウザ需要が立証済みとは説明しない。

### SEARCH-02: ページごとの検索情報

- LPとガイドに、内容に対応する固有のタイトル・説明文・分かりやすい見出しを用意する。
- ガイドは独立したURLとcanonicalを持つ。LPとガイドを同一内容のページとして扱わない。
- ガイドの紹介リンクと、記事からの導入リンクは、リンク先の内容が分かる文章にする。
- YouTubeガイドにも固有のtitle/description、canonical、`og:url`を設定する。YouTube画面と誤認させる共有画像は付けない。公開URLは `https://scene-memo.pages.dev/guide-youtube`、ソースファイル名は `guide-youtube.html`。
- 2つのガイドの内部リンク、canonical、`og:url`、サイトマップは拡張子なしの公開URLへ統一する。Cloudflare Pagesが `.html` を拡張子なしURLへ転送するため、`.html` のURLを新しいリンク先として使わない。
- LPとFANZAガイドに、canonicalと一致する`og:url`、ページ固有のOpen Graph title/description、公開絶対URLの`og:image`、`twitter:card=summary_large_image`を設定する。共有画像は1200×630 PNGとし、実画面とサンプルデータの説明が一致するようにする。
- 今回の公開ではURL・ガイド・ZIPが意図した内容を返すことを確認済み。以後の更新時も、公開後にリンク先とZIP取得を確認する。
- 2026-10-25に日本語共有カード`scene-memo-LP/assets/og-share-ja.png`を作成。LPとガイドのSNSメタデータ、本番画像の表示を確認済み。X等のカード展開表示は未確認。

### SEARCH-03: 多言語URLとクロール基盤（後続の提案）

- LPに日本語・英語・簡体字中国語・韓国語の固定URLを用意する案とする。パス例は `/ja/`、`/en/`、`/zh-cn/`、`/ko/`。最終パスは未決定。
- ブラウザの優先言語判定は初回の案内に使い、言語を選んだURLではその言語の本文を安定して表示する。対応する言語への切替リンクを用意する。
- 主要な説明を初期HTMLで読める構成にし、各言語版の `hreflang` とcanonicalを整える。
- 公開済みページのサイトマップ、robots設定、ホスティング側のアクセス制限を確認する。Googlebot、Bingbot、OAI-SearchBotのアクセス方針を整理する。
- 2026-10-25に `scene-memo-LP/robots.txt` と `scene-memo-LP/sitemap.xml` を本番へ反映。robots.txtはHTTP 200・`text/plain`、sitemap.xmlはHTTP 200・`application/xml`。Search Consoleの所有権確認は成功。初回のsitemapレポートは「取得できませんでした」・検出0件だったため、公開URLが正しく応答することを確認して再送信し、送信成功表示を確認。レポートの処理結果は未更新。前回の公開確認ではサイトマップにトップページと2つのガイドが含まれていたが、ガイドのcanonical・`og:url`・sitemap URLは `.html`、実際の転送先は拡張子なしで不一致だった。今回ソース上の公開URLを拡張子なしに統一したが、本番反映は未実施。
- ガイドの全言語展開は別の段階で検討する。未翻訳のガイドへ、存在しない言語版のリンクを作らない。

### SEARCH-04: AIの回答で参照される説明

- 製品名、対応サイト・環境、保存対象、無料枠、価格、導入方式、外部通信、非公式ツールであることを、読者が確認できる文章や表にまとめる。
- 「LP・手順書は4言語、拡張UIは日本語・英語」という範囲を区別する。
- 実操作と説明を一致させ、質問に短く答えたあと、必要な手順や制限を説明する。
- 構造化データを追加する場合はページで読める事実と一致させる。存在しない評価や利用者数を作らない。
- AI専用ファイル、特殊なマークアップ、記事数を、検索・AI掲載の保証条件として扱わない。AIへの掲載や引用を保証しない。

## 6. 計測要件

| 段階 | 確認すること |
|---|---|
| 発見 | Search Consoleで取得・インデックス状態、検索語、表示、クリックを確認 |
| AIでの参照 | 利用できる場合、Bing Webmaster ToolsのAI引用情報などを確認。取得できない指標は未取得と記録 |
| 訪問 | GA4標準レポートで参照元とLP・ガイドのページビューを把握 |
| 導入への関心 | ページ閲覧を確認する。ZIPボタンのクリックは計測しない |
| 導入完了 | 任意の申告等の根拠を得た場合に別途記録。ZIPクリックから推計しない |

コメント本文、動画ID、動画タイトル、メモ時刻などの拡張内データを、集客計測のために取得しない。Google Analytics 4（測定ID `G-29BQ8L3ST0`）でLPと2つのガイドの標準ページビュー・参照元を計測する。GA4はCookieなどの識別子を使い、ページビューに加えてセッション開始、新規訪問、ページ上の利用時間を自動収集するため、計測範囲とデータ取扱いを公開説明する。Googleシグナル、広告向けシグナル、拡張計測は無効とし、初期実装ではカスタムイベントを送らない。

公開後は約4週間を初回観察の目安とする。表示がないことだけで需要ゼロとは判断せず、クロール・インデックス・内容・観察期間を確認する。

2. ガイドを翻訳する範囲と順序。YouTubeガイドはローカル下書きを確認してから公開判断する。
3. GA4タグと公開説明の本番反映、3ページからGoogle Analyticsへのcollectリクエスト、Cloudflare Web Analyticsの停止と公開ページからBeaconが消えたことを確認済み。GA4リアルタイム集計画面での `page_view` 確認はGoogleログインが必要なため未完了。

認証情報の値をチャットやリポジトリに記載する必要はない。追加費用0円を維持する間は、投稿API認証の確認・利用を行わない。
